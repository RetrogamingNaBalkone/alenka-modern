# Разбор оригинальной «Аленки»

Дата: 7 ноября 2026 года. Инструменты: **Ghidra 12.1.2 Headless**,
**DOSBox Automation 0.85.1 (7567ec4)**. EXE и оба крупных файла ресурсов
импортированы в проект `diagnostics/analysis/ghidra/project/Alenka.gpr`.
Ghidra MCP не обнаружила запущенного экземпляра; анализ выполнен локальным
headless-анализатором Ghidra. Исходная поставка не изменялась.

## Что установлено

`ALLE.EXE` — 16-битный DOS MZ, а не Windows PE. Строка среды сборки:
`Turbo C++ - Copyright 1990 Borland Intl.`. Ghidra использует язык
`x86:LE:16:Real Mode:default`, начальный CS `1000`, сегмент данных `1853`.
Соответствие файлового смещения данным: `0x200 + 0x8530 + offset_in_DS`.
После объявленного MZ-образа есть `0x35ff` дополнительных байтов с файлового
смещения `0xeb10`; их назначение пока не установлено.

В `1000:25f6` инициализация вызывает `1000:58d7` с параметрами
`(0x10, 30000, 1)`. Функция `58d7` выбирает BIOS EGA **640×350×16**.
Это дополнительно проверено `video/frame/info` запущенного DOS-оригинала:
BIOS mode 16, graphics_standard EGA, width 640, height 350.
Журнал DOSBox сообщает поправку пикселя `35:48` (ширина:высота).

Оболочка SDL2 использует **borderless fullscreen window**
(`SDL_WINDOW_FULLSCREEN_DESKTOP`), сохраняя разрешение рабочего стола.
В Windows EXE встроен ресурс RT_MANIFEST / ID 1 с **Per-Monitor V2 DPI awareness**
и резервным Per-Monitor для старых систем. SDL получает тот же запрос до
инициализации видео. Windows не выполняет дополнительное bitmap-масштабирование:
приложение рассчитывает вписывание по пикселям `SDL_GetRendererOutputSize`.
Механизм соответствует [рекомендации Microsoft о DPI-манифесте](https://learn.microsoft.com/en-us/windows/win32/hidpi/setting-the-default-dpi-awareness-for-a-process)
и [документации SDL о DPI awareness](https://wiki.libsdl.org/SDL2/SDL_HINT_WINDOWS_DPI_AWARENESS).

Отсюда конечное отношение сторон `640 / (350 * 48/35) = 4/3`.
Рендерер хранит **все 350 строк**, не обрезает кадр до 344 строк и не считает
640×350 изображением с квадратным пикселем. Карта экрана имеет 44 ряда тайлов
высотой 8 пикселей; последние две строки нижнего ряда находятся за границей EGA.

## Ресурсы

| Файл | Байт | Установленный формат / состояние |
|---|---:|---|
| ALLE.EXE | 73999 | DOS MZ, код, таблицы клавиш и константы графики |
| ALLE.LIB | 93696 | GRED Library: палитра и планарный атлас 320×584 |
| ALLE.FLD | 43872 | GRED Field: 80×274 адресов тайлов |
| ALLE.TXT | 9931 | Исходные строки упражнений, CP866, CRLF |
| ALLE.CTN | 32 | Назначение и структура пока не подтверждены |
| ALLE.GCH | 0 | Пустой исходный файл, сохранён в поставке |
| ID.LGO | 903 | Текстовые байты DOS / псевдографика; роль в приложении не подтверждена |

`LIB` не является DLL или объектной библиотекой. В Ghidra LIB/FLD импортированы
как Raw Binary; скрипт `ResourceAnalysis.java` размечает заголовки и данные.
Экспорт значений: [LIB](evidence/ALLE.LIB.txt), [FLD](evidence/ALLE.FLD.txt).

### ALLE.LIB

Первые поля — little-endian uint16:

| Смещение | Значение | Смысл |
|---|---:|---|
| 0x00 | 0 | Версия |
| 0x02 | 7 | Начальный Y в сохранённом заголовке; не пропуск строк в файле |
| 0x04 | 583 | Последняя строка атласа |
| 0x06 | 39 | Последний байт строки, т. е. stride 40 |
| 0x08, 0x0a | 8, 8 | Размер тайла |
| 0x0c, 0x0e | 40, 73 | Число столбцов / рядов тайлов |
| 0x10 | 1 | Есть палитра |
| 0x12 | 17 × RGB uint16 | Компоненты 0…3 соответствуют 0, 85, 170, 255 |
| 0x78 | GRED Library | Сигнатура |
| 0x100 | 4 × 40 × 584 байта | Плоскости 3, 2, 1, 0, старший бит — левый пиксель |

Порядок плоскостей подтверждён `1000:527a` (маски 8, 4, 2, 1).
Цвет с индексом 1 — **RGB (0, 0, 170)**, оригинальный фон рабочего экрана.
Индекс 16 не используется как индекс пикселя четырёхплоскостного атласа.
Это не основание применять его к полям современного окна.

### ALLE.FLD

Заголовок 32 байта: `uint16 version`, `uint16 legacy_pointer`, `uint32 count`,
`uint16 width`, `uint16 height`, сигнатура `GRED Field` и оставшиеся служебные байты.
В поставке count=21920, width=80, height=274.
Далее `count` little-endian uint16. Для получения адреса в одной плоскости
атласа из каждого значения вычитается **16000**.

`atlas_x = (address % 40) * 8`, `atlas_y = address / 40`.
Это адрес байта начала тайла, а не линейный номер тайла. Функция `1000:54f1`
при загрузке корректирует значения на `30000-16000` для размещения в EGA RAM.
Порт хранит смещение от начала атласа, без DOS-сегментов и видеопамяти.

Границы экранов и фрагментов подтверждены вызовами blit в EXE:

| Начальная ячейка FLD | Использование |
|---:|---|
| 0 | Заставка, 80×44 |
| 0x0dc0 = 44×80 | Основной фон и клавиатура, 80×44 |
| 0x1a40 = 84×80 | Зелёные клавиши |
| 0x1ef0 = 99×80 | Зелёные нажатые клавиши |
| 0x23a0 = 114×80 | Красные клавиши |
| 0x2990 = 133×80 | Нажатые обычные клавиши |
| 0x2f80 = 152×80 | Обычные клавиши |
| 0x3570 = 171×80 | Основа экрана статистики |
| 0x4330, 0x4479 | Фрагменты верхнего меню |
| 0x47e0 = 230×80 | Справка, 80×44 |

## Опорные функции EXE

| Адрес Ghidra | Назначение |
|---|---|
| 1000:25f6 | Инициализация, загрузка LIB/FLD/TXT, заставка, основной цикл |
| 1000:58d7 | Выбор видеорежима и экранных структур |
| 1000:518f, 1000:527a | Загрузка GRED Library и четырёх плоскостей |
| 1000:54f1 | Загрузка GRED Field и коррекция адресов |
| 1000:49a3, 1000:4a4c | Вывод тайлов для stride 40 / 80 |
| 1000:5a28 | Копирование прямоугольника ячеек |
| 1000:6068 | Номер тайла → адрес в плоскости |
| 1000:1a97 | Показ справки |
| 1000:1ac2 | Восстановление основного экрана / статистики |
| 1000:0342, 1000:06b8 | Выделение верхнего меню |
| 1000:0806 | Отображение строк упражнения |
| 1000:0eaf | Scan code → символ с учётом языка, Caps Lock и Shift |
| 1000:0f46, 1000:186e | Вариант изображения клавиши, подсказки и подписи |
| 1000:17d4 | Индикаторы Num/Caps/Scroll Lock |

В DS `0xb8 + scan_code*5` лежат x, y, ширина, высота, группа пальца.
В DS `0x315…0x4ec` — английские и русские раскладки для разных модификаторов.
Константы исходных фрагментов — DS `0x90…0xb6`.
Графическая основа порта читает эти данные из поставляемого EXE.
DOS-код порт **не исполняет**, внешнего эмулятора для его запуска не требуется.

## Проверка достоверности

Эталон снимался в отдельной копии исходной поставки под DOSBox Automation:
свежий запуск → заставка → Enter → справка → Space → основной экран.
Снимки — native raw framebuffer 640×350, без шейдеров и коррекции цвета;
хранятся в `.raw.gz` со сжатием gzip без потерь. PNG используются для просмотра.
В основной сцене начальная раскладка русская, Caps Lock включён, все клавиши отпущены.

Сравнение всех 224000 пикселей каждого экрана: **0 отличий** у заставки,
справки и реконструированного начального рабочего экрана. SHA256 исходных
raw-снимков после распаковки и переносимые FNV-отпечатки нормализованных BGRA:
[reference-hashes.json](evidence/reference-hashes.json).
FNV-проверки включены в обычный `core-tests`; с `build.ps1 -Reference`
дополнительно проверяется каждый пиксель свежих снимков в `diagnostics/validation/reference`.
Эталон захватывает `tools/capture_reference.py`; API должен быть запущен
на свежей заставке оригинала, токен передаётся через `DOSBOX_API_TOKEN`.

В Windows выполнены реальные переходы SDL windowed → fullscreen desktop → windowed,
проверены флаги окна и состояние курсора, включая потерю фокуса.
После добавления DPI-манифеста проверены сам ресурс внутри собранного EXE
(`tools/verify_manifest.py`) и фактический Per-Monitor V2 контекст HWND
через `GetWindowDpiAwarenessContext` / `AreDpiAwarenessContextsEqual` в smoke-тесте.
Перенос между физическими мониторами с разным DPI пока отдельно не проверялся.
Вывод 1280×720: область 960×720 с x=160; вывод 600×1000:
область 600×450 с y=275. Снимки проверены визуально и скриптом
`tools/verify_layout.py` относительно оригинального framebuffer.

## Перенесённое поведение и приёмка

Тренажёр работает на C++/SDL2: ввод, меню, раскладки, подсказки, опечатки,
сложность, ритм, таймер, переходы по строкам, графики статистики и обнуление.
Курс читается непосредственно из ALLE.TXT. Начальный CRLF пропускается по
`1000:27a1`; внутренние пустые строки сохранены вместе с их номерами.
Автоматически пройдены **170 строк и 9589 символов**, с настоящими для ядра
событиями Caps Lock, Shift и переключением раскладок двумя Shift.

Восстановлена sparse-switch таблица основного цикла `1000:4268/428c`
и статистики `1000:219f/21bf`. Скрипт `RecoverSwitches.java` задаёт Ghidra
границы и назначения непрямых переходов, после чего декомпилирует все ветви.
Восстановлены пропущенные обработчики IRQ8/IRQ9 и функция `1000:0203`.

В `tests/scenarios` сохранены независимые отпечатки DOS-кадров:

- 45 кадров меню, настроек, справки и родных заглушек;
- 21 кадр удержанных клавиш, обоих Shift, Caps Lock и Enter;
- 4 графика с явно одинаковыми исходными счётчиками в оригинале и порте.

Все **70 кадров совпадают полностью**. Эталоны графиков проверяют как общую
нормировку, так и неполные тайлы столбцов. Нормировка — максимум суммы
среднего времени и ошибок по видимым символам, а не отдельный максимум времени.
Частота часов следует PIT: 1193182 / 16384 тиков/с; интервал ритма —
целочисленное `4380 / rhythm` тиков. Повтор выбора строки: сначала 24 тика,
затем по одному. Есть отдельные проверки таймаута и отпускания клавиш.

Живое сравнение времени реакции между эмулятором и нативной программой
зависит от длительности обработки старого DOS-кода, задержек инъекции клавиш
и отставания захваченного кадра от таймера. Эти временные величины не выдаются
за одинаковые. Для попиксельной проверки формулы графиков
`check_statistics.py` явно задаёт одни и те же счётчики обоим приложениям.

В живом Windows-окне проверены заставка → справка → упражнение, набор,
Escape → статистика, Enter → упражнение, Alt+Enter → borderless → окно.
Обнаружен и закрыт путь виртуальных клавиш без scan code, которые SDL2
отбрасывала: `windows_input.hpp` дополняет только такие сообщения.
Обычные аппаратные сообщения остаются в SDL2. Потеря фокуса отпускает
клавиши в ядре и прекращает повтор выбора строки.
Alt+Enter перехватывается до обработки упражнения вместе с Alt, поэтому
переключение режима не засчитывается как ошибочный ввод даже при включённых опечатках.
Windows EXE имеет GUI subsystem; скрипт сборки явно ожидает завершения
smoke-процесса и проверяет его exit code перед упаковкой.

## Возможности, отсутствующие в оригинале

Обработчик `1000:2011`, ветви 2…6, выводит исходное окно из FLD `0x45bc`:
**«Не реализовано!!!»**. Это кнопки языка, динамика, печати и дискет.
В версии 1.0 порта они оставлены такими же. В версии 1.1 кнопка динамика
переключает новые синтезированные сигналы, а кнопка «РУС / ENG» выбирает
русский или новый английский курс со сбросом прогресса и статистики.
Заглушки печати и дискет сохранены. Переключение раскладки двумя Shift
работает независимо от выбора курса.
Статистика не сохраняется между запусками; свои форматы сохранения не добавлены.

В исследованных звуковых путях не найдено программирования PIT channel 2:
`1000:64b4` задаёт PIT channel 0 для часов, а записи в порт 61h в
`1000:6246` переключают только бит 7 подтверждения клавиатуры, сохраняя
биты PC Speaker. Новые звуковые сигналы по этим записям не синтезируются.
Сигналы ошибки и метроном в версии 1.1 добавлены по решению пользователя;
это развитие программы, их частоты и длительности не извлечены из оригинала.
Проверки DOS-заглушек динамика и языка исключены из `menus.trace`, остальные
69 эталонных кадров сохранены. Переключение курсов и полный английский курс,
а также переключение звука, индикацию отключения,
события ошибок и темп проверяет `trainer-tests`, вывод PCM через SDL,
приоритет сигналов и отсутствие устройства — `audio-tests`.

Исходные семь файлов остаются в `original/ALENKA` для анализа и сверки;
они защищены проверкой SHA-256 при сборке. В релиз входят только используемые
LIB/FLD/TXT и `ALENKA.DAT`: 0x1300 байт таблиц и констант из EXE по смещению
0x8730. Код DOS-программы, CTN/GCH и ID.LGO в релиз не включаются.
Отдельные проверки подтверждают совпадение кадров и курса после такого извлечения.

## Ограничения проверки

Linux-сборка подготовлена, но её запуск на Linux пока не проверен.
Перенос между физическими мониторами с разным DPI отдельно не проверялся.
Резервные режимы DPI старых Windows также не проверялись запуском.
Автоматическая декомпиляция Ghidra содержит предупреждения о 16-битных указателях,
перекрывающихся глобальных переменных и непрямых переходах. Её нельзя компилировать
как готовый исходник или принимать спорные сигнатуры функций без проверки ассемблера.
